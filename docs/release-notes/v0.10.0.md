# v0.10.0

## Workspace: An "Active Projects" Group

- A new **Active Projects** tab sits on the right of the group bar, set apart from your real groups. It gathers every project with a live agent session, **most recently active first**, so the work that is actually running is always one click away no matter which group it lives in
- It's a view, not a group: projects stay in the group you filed them under, and the tab re-prunes itself as sessions come and go. Clicking it again while it's already open drops any project that has since gone quiet
- **Workspace → Settings** controls whether it appears and **how many projects it lists** (1–20, default 5). Projects past the limit are simply left out — they're still reachable from their own group. Existing workspace files get the group switched on with the default limit

## Workspace: Tabs Frame the Work They Own

- The group tab bar and the project tab bar each now carry an **accent rail along the edge facing the content**, which continues down the sides and across the bottom to box in the area that tab owns. The active tab leaves a gap in its own rail, so it reads as joined to the workspace below it rather than floating above it
- The two rails use **deliberately different hues** — one for the group, one for the project — so with grouping in use you can see at a glance which project sits inside which group, instead of two nested frames in the same colour
- Tabs are outlined on three sides with slightly rounded top corners, and a project tab that isn't current sits a shade darker than the strip it lives on. The framing follows the toolbar wherever you dock it — top, bottom, left or right

## Workspace: Opening a Workspace Shows Its Progress

- Opening a workspace with a lot of projects used to look like a hung window. There's now a **modal overlay with a spinner, the project being opened, a counter and a progress bar**, and it swallows clicks while the restore runs so a stray double-click can't land somewhere unintended
- The restore yields between projects rather than blocking, which is what lets the spinner actually spin
- A single-project workspace gets the spinner without the counter and bar — there's nothing to count

## Chat: The Agent Tells You When It's Still Working

- A session with **subagents or background tasks still running** no longer reads as finished. Background work is tracked as it starts and stops, and the session status and the tab's status diamond reflect it — so "idle, but three subagents are still going" is now visibly different from "done"
- **A question or a permission prompt has its own sound**, distinct from the one a finished turn makes. A turn parked waiting on you sounds different from a turn that has actually completed
- A background tab that finishes work while you're elsewhere flashes its diamond green until you look at it
- The session status line now **prefixes a warning glyph while permissions are bypassed**, so a session running unattended in danger mode says so

## Chat: Composer

- **Send is now a split button.** Send stays the default action; the dropdown holds the secondary ones, including scheduling a message for later — so a pending scheduled message no longer needs its own permanent button competing for space
- A **floating clear button** appears over the composer when there's something to discard, dropping the drafted text and any queued attachments in one click. It floats rather than taking a slot, so it costs the composer no room when there's nothing to clear
- The input box **stays usable while a turn is running**, so you can draft the next message without waiting

## Markdown: Copying Out of the Transcript

- Rendered tables get a small **"Copy table"** button in their top-right corner, which copies the whole table and flashes a confirmation. Selecting across a rendered table by hand doesn't work — each cell is its own text host — so there was previously no way to get one back out
- **Copying a selection now produces markdown.** Links come out as `[text](url)` instead of losing their target, and internal file links, whose URIs mean nothing outside Agent Dock, come out as plain text rather than as a dead `agentdock-file://` URI

## Accounts: Fixed Agent Dock Signing Your Accounts Out

- **Agent Dock no longer refreshes Claude OAuth tokens itself.** The usage indicator had started performing its own refresh-token grant and writing the rotated tokens back into an account's `.credentials.json`, every 90 seconds, per account. But refresh tokens are single-use and rotate on every use — and the `claude` CLI subprocesses Agent Dock spawns against that same config directory refresh and write it too. The two writers raced, a spent refresh token eventually got re-presented, and the server revoked the entire token family. The result was configured accounts being **permanently signed out mid-session**, with no way back in short of a fresh login
- The usage service is now **strictly read-only** with respect to `.credentials.json`. The CLI is the sole owner of the token lifecycle for a config directory. When a stored access token has lapsed, the usage figure simply goes quiet until the CLI renews it on next use — a slightly stale usage number is worth far more than a working login
- **A signed-out account now looks signed out.** The login check only tested that `.credentials.json` existed. When the CLI's refresh is rejected it rewrites that file in place with the tokens blanked and `expiresAt: 0`, keeping the surrounding metadata — so the file still existed and the account was still reported as signed in. The check now requires an actual non-empty token
- Account status in **Claude Accounts** and in the start-panel account picker is now driven by login state rather than by the email address. The email lives in `.claude.json`, which survives a logout, so a revoked account used to display its address and read as perfectly healthy — with nothing hinting that **Log In** was the thing to click. Signed-out accounts now show *"signed out (click Log In)"* alongside the email
- **A turn that fails now says so.** Error results were only reported when the CLI sent a structured `errors` list. An auth failure arrives instead as a synthetic result carrying the reason in its `result` text, with zero tokens and zero cost — so those turns completed in complete silence, looking like the session had simply answered with nothing. The reason is now always surfaced
- When a turn fails having done no work and its account is signed out, the chat now says which account is affected and points at **Claude Accounts → Log In** to fix it, instead of leaving a raw CLI message to interpret

## Accounts: Sign-in Actually Prompts for a Login

- **Log In now runs the CLI's dedicated `claude auth login` command.** It previously opened a bare interactive `claude` session and relied on the CLI prompting for a login — which it doesn't do when a credentials file is already present, even a hollow one with its tokens blanked. The window just sat at an ordinary session prompt, with a printed hint to type `/login` manually. It now goes straight into the browser sign-in regardless of what's on disk
- The login page is **pre-filled with the address that account was last signed in as**. With several accounts the login pages are otherwise indistinguishable, and authenticating the wrong Claude login into a given account was an easy mistake to make
- **The terminal window now closes itself** when the sign-in completes, instead of dropping back to a leftover command prompt. It stays open only if the login failed, so there's an error left to read
- The config directory is now passed to the login process through the process environment rather than assembled into a shell command line, removing a quoting hazard on paths. A batch-shim install of `claude` still falls back to running through `cmd`
- **The account list refreshes itself when a sign-in finishes** — no more completing a login and then having to click Refresh to find out whether it worked. Progress and the result are reported inline in the dialog instead of in a message box that would cover the list it was talking about, and the action buttons disable while a sign-in is in flight
- If the login process is still running once valid new credentials have landed, its window is now closed automatically, so a stray terminal can't sit there looking like an unfinished sign-in

## Accounts: Usage, Per Login

- The usage popup now shows **every configured login**, each in its own group box tinted with that account's accent colour, so the bars line up with the account they belong to instead of being one anonymous total
- Accounts are fetched **one at a time**, and an account that gets rate-limited backs off for as long as the server asks rather than being hammered on the next tick
- **A lapsed access token is reported as stale, not as an error.** Nothing is wrong with the login — the CLI renews the token the next time you send a message — so the figure just goes quiet instead of crying wolf about a healthy account
- **The login you pick on a project's Start panel is remembered against that project**, so the picker reopens on the same account next time rather than defaulting back to the first one

## Chat: Multi-line Answers to AskUserQuestion Prompts

- Answers typed into an `AskUserQuestion` prompt can now span **multiple lines**

## Removed

- **Voice dictation.** The microphone button and the speech service are gone. Agent Dock now simply targets Windows 10 version 2004 or later, with no feature that varies by build

## Fixes

- The **Git status panel** no longer throws when you switch away from a tab, or close a project, while a file-change refresh is still pending
- **App Settings** no longer throws while opening, from the navigation list selecting its first item before the dialog had finished loading
